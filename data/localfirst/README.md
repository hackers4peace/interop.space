# Local-First data

Catalog records for **Local-First**: the organization, the next Local-First
Conf edition and its city, and the software listed in the local-first
landscape. The files are generated by the `localfirst` Temporal workflow from
the public pages below, so this directory carries the notes and the workflow
carries the mapping.

Snapshot: **2026-11-16**.

## Files

| File | Contents |
| --- | --- |
| `organizations.nq` | The Local-First organization, subject `https://www.localfirst.fm/` |
| `locations.nq` | Adds the conference page as a source on the existing Berlin node |
| `events.nq` | The next Local-First Conf edition |
| `software.nq` | Local-first tools from the landscape, as `doap:Project` records |

Everything in this directory except this README and `.gitignore` is
generated by the dump and gitignored: the four `.nq` stage files, the worker /
client / failure logs, temp files and the worker-ready marker.

## Sources

### Organization

<https://www.localfirst.fm/> is the umbrella site: podcast, landscape,
community Discord and links to the conference. The organization record uses
that URL as its subject, which is also the `ex:sdo` value on the event and the
UI's SDO filter.

### Event

<https://www.localfirstconf.com/> is the current conference page. The workflow
reads:

- `<title>` for the event name (`Local-First Conf 2027`);
- the date heading (`25th - 26th may, 2027 in Berlin.`) for the date range and
  the city;
- the anchor whose text starts with `Venue` for the venue name
  (`Festsaal Kreuzberg`);
- the `Berlin, Germany` line in the footer for the country.

The page also lists community socials on 24 and 27 May. They are part of the
conference week but outside the two conference days, so they are not separate
event records.

### Software

<https://www.localfirst.fm/landscape> is the comparison table. Its data is
maintained in per-technology repositories and compiled into a generated
snapshot by the landscape's own workflow. The import uses that snapshot rather
than the rendered page:

- <https://github.com/localfirstfm/local-first-landscape/blob/main/landscape-fetch-content/src/repos.ts>
  lists the technologies (`id: '…'` entries);
- <https://github.com/localfirstfm/local-first-landscape/tree/main/landscape-content-snapshot/src/generated>
  holds one `data.json` per technology id, the same files the landscape site
  builds from.

At this snapshot `repos.ts` lists **22 technologies** and every `data.json`
was fetched. One missing or malformed file fails the software stage instead of
publishing a partial catalog. The snapshot's own `__generated.lastUpdated`
value becomes `dcterms:modified`.

## RDF mapping

### Organization

`https://www.localfirst.fm/` is an `ex:Organization` with `ex:name`
"Local-First", `ex:homepage` and `ex:source` pointing at the same URL, and
`ex:logo "/logos/localfirst.svg"`.

### Locations

Berlin already exists in the curated catalog. `data/locations.ttl` publishes
`urn:uuid:ec0f30fc-cea2-4f7d-b80b-50be521fa360` as "Berlin, DE" (region
"Europe"), and that is the node the Atmosphere, Mozilla and IndieWeb local
groups point at. The Local-First import **reuses that node** instead of adding
another Berlin, so the conference event appears on the same city page as those
groups. `locations.nq` therefore only adds the conference page as another
`ex:source`; name, region and coordinates stay in `data/locations.ttl`.

A future edition in a different city gets its own `ex:Location` record, with
`ex:name` as `City, Country`, `ex:region` as the country, the conference page
as `ex:source`, and a UUIDv5 subject derived from
`localfirst:location:<country>:<city>`. The conference page publishes no
coordinates, so such a node has none until the base catalog adds the city.

### Events

The event carries:

- `ex:sdo <https://www.localfirst.fm/>`;
- the published title as `ex:name`;
- the two conference days as `ex:startDate` / `ex:endDate`, using the catalog
  convention `00:00:00Z … 23:59:59Z` for the first/last day (no times are
  invented);
- `ex:location` as `Venue, City, Country` and `ex:atLocation` pointing at the
  city node (for Berlin, the reused curated node above);
- `ex:source`, the conference page.

Event subjects are UUIDv5 values derived from
`localfirst:event:<slug>`, where the slug comes from the published title. A
title that changes year to year therefore produces a new subject, which is what
keeps annual editions distinct.

### Software

Each technology is a `doap:Project` with:

- `doap:name` and `doap:shortdesc` from `Name` and `Description`;
- `doap:homepage` and `doap:repository` from `Website` and `GitHub`, only when
  the value is an absolute http(s) URL;
- `doap:license` from `License`, verbatim. A landscape value of `None` means no
  license is recorded, so those records carry no `doap:license`;
- `doap:programming-language` for every `AppTarget.LanguageSDK` value;
- `ex:maturity` from `MaturityLevel`;
- `ex:platform` for every `AppTarget.Platform` value;
- `ex:deployment` for every `Deployment` value;
- `ex:siloId "urn:localfirst:software:<id>"` with the stable landscape id;
- `ex:source` (the landscape page) and `dcterms:source` (that technology's
  `data.json` in the snapshot repository);
- `dcterms:modified` from the snapshot's `__generated.lastUpdated`.

Subjects are UUIDv5 values derived from `localfirst:software:<id>`, using the
stable id from `repos.ts` (for example `automerge` or `y-sweet`). A renamed
technology keeps its subject; a duplicate id is rejected because it would
collide.

Values are reproduced as published. The landscape has inconsistent casing
(`Typescript`, `Production-ready`) and some non-language SDK labels (`HTTP`,
`JSON`, `C# - .NET`); the import does not normalize them.

## Refreshing

The workflow skips any stage whose `.nq` already exists. To refresh after the
conference page or the landscape changes, delete the stage files and rerun:

```sh
rm -f data/localfirst/*.nq
devbox run dump:localfirst
```

The same import can run without Temporal/Dagger, which is useful for checking a
parser change:

```sh
cd typescript
STAGES_DIR=../data/localfirst bun run src/localfirst/run.ts
STAGES_DIR=../data/localfirst bun run src/localfirst/run.ts software
```

`bun test src/localfirst` covers the conference-page parser, the landscape id
list and the RDF builders.

## Seeding

`scripts/fuseki.ts` treats the directory as a generated export, like
`data/fedidb`:

```sh
devbox run seed -- localfirst
```

`devbox run seed -- all` also includes it. `seed -- static` only selects the
curated `.ttl` files, so it does not seed this directory.

## Limits

- The conference page is a Webflow page without structured event data. The
  parser matches the date heading, the `Venue …` link and the footer city line;
  a redesign makes the event stage fail loudly rather than publish guessed
  dates.
- The landscape snapshot is what the landscape site displays, not the
  individual per-technology repositories. New technologies appear after the
  landscape refreshes its snapshot.
- Neither the conference page nor the landscape states a data license. The
  records link back to both sources, and each software record links to its
  upstream `data.json`. Logos are not copied from the landscape; only the
  Local-First mark in `ui/public/logos/localfirst.svg` is stored locally.
- Licenses, maturity levels and deployment values are published strings, not
  normalized SPDX or enum values.
- The event is a calendar date range; the page does not publish session times.
- Berlin reuses `urn:uuid:ec0f30fc-cea2-4f7d-b80b-50be521fa360` from
  `data/locations.ttl`. Seeding only `data/localfirst/*.nq` without the curated
  static files leaves the event's location link unresolved; seed the static
  files too (`seed -- all`, or `seed -- static localfirst`).

## Related records

The SDO card lives in `ui/src/data/sdos.json`; `?sdo=localfirst`,
`?sdo=local-first` and `?sdo=localfirstconf` all resolve to
`https://www.localfirst.fm/`. The logo is
`ui/public/logos/localfirst.svg`: the mark from the localfirst.fm header, saved
locally with its fill set to the site's amber (`#fbbf24`) so it stays visible on
the catalog's white logo tiles. The shape is unchanged.

The Info page credits both upstream sites under **Attributions**. The workflow
itself lives in `typescript/src/localfirst/`; its queue is `localfirst` and its
Dagger entry point is `dump-localfirst`.
